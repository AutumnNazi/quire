# Quire

> Quire:一篇文章里的一叠折叠配页,也可以是一个"夹页"的错拼。

**Read later, on your own disk.**

**剪藏,留在你自己磁盘上。**

---

本地优先的稍后读工具。文章剪下来就是你自己的 Markdown 文件——不是某个服务的私有数据库里的一个 blob。没有账号、没有云端、没有订阅,**不装浏览器插件也能完整使用**。
```
~/Documents/Quire/
└── clips/
    ├── 2026-09-28-m8x2k9a4-example-com.md
    ├── 2026-09-28-m8x2k1b7-github-com.md
    └── 2026-09-27-m7y0z2c9-sspai-com.md
```

用记事本、Obsidian、任何编辑器打开都能读。想换软件、想备份、想直接扔进 Git——随便。

## 怎么剪藏

**复制,然后粘贴。** 就这两步。

1. 在任意文章页里选中正文,`Ctrl`+`C`
2. 切到 Quire,按 `Ctrl`+`V`(或点工具栏上的「粘贴剪藏」)

不想切窗口?打开工具栏的**「监控剪贴板」**开关(默认关闭),之后只要在别处复制了内容,Quire 会在窗口底部弹一条提示,问你要不要存。**它只通知,不自动保存**——自动存等于替你做决定,而且开着的时候你复制的密码、验证码、快递单号都会往里弹。

## 浏览器扩展(可选,建议装)

剪贴板有个绕不开的短板:**它只给得着你划选的那一块,而且拿不到页面元数据**。想存整篇、想要作者和发布时间,就得靠扩展。

扩展是**可选的**,不装也能用,装了多几个字段:

| | 只用剪贴板 | 装了扩展 |
| --- | --- | --- |
| 正文 | 你划选的那部分 | **整篇** |
| 标题 | 首个 h1 | 页面标题 |
| 作者 / 发布时间 | ✗ | ✓ |
| 封面图 | ✗ | ✓ |
| 摘要 | 从正文第一段兜底 | 页面摘要 |

**扩展不新增任何端口。** 它把整页连同元数据写进剪贴板,Quire 用现成的 `Ctrl`+`V` 接住——走的是和上面一模一样的链路:

```
你在别处 Ctrl+C  /  点一下扩展图标
   ↓  Windows 剪贴板(HTML Format + Unicode Text)
Quire 每 700ms 比对一次内容指纹(仅在开关打开时)
   ↓  emit "clipboard-changed"
前端弹提示 → 你点「保存」
   ↓  Defuddle 在 webview 里把 HTML 转成 Markdown
vault/clips/2026-09-28-xxxx-example-com.md
```

```bash
pnpm ext:build
```

然后打开 Chrome/Edge 的扩展管理页(`chrome://extensions`),开启开发者模式,加载 `apps/extension/dist`。

用的时候点一下扩展图标,图标上冒出 ✓,内容已经在剪贴板里了。开着「监控剪贴板」的话 Quire 会直接弹提示,连切窗口都省了。

## 为什么不把扩展做成必需品

第一版就是「浏览器扩展 + 本机 HTTP 服务」,推翻它的理由不是技术不行,而是**门槛不对**:主打零门槛的工具,第一步就要求装扩展、认扩展 ID、在权限弹框点同意,大多数人在这一步就流失了。

所以现在插件是可选的增强,不是前提。**不装的人得到的是一条完整的、能用的路径,不是残废版。**

## 为什么又是一个稍后读工具

因为大多数"稍后读"的收藏其实是租的。

云端笔记服务倒闭之后,你的两千条笔记去哪了?常见答案是:变成了一堆格式互不兼容的导出文件,链接全部失效。它们的搜索索引是公司的资产,不是你的数据。

Quire 的立场很简单:

- **正文是文件,不是记录。** 每个剪藏都是一个独立的 `.md`,带 YAML frontmatter。任何工具都能读。
- **索引随时可以删。** 全文搜索索引(路线图里)是可重建的派生物,删掉不影响一个字节的数据。
- **数据在你能看见的地方。** 工具栏上永远显示着剪藏目录的完整路径,点一下直接在文件管理器里打开。
- **不开监听端口。** 早期版本靠 localhost 上的 HTTP 服务接收扩展推来的内容,现在这个服务整个拆掉了——留着就等于在你机器上常驻一个监听端口,给同浏览器的恶意网页留了个可攻击面。拆掉比加防护干净。

## 安装

需要 Windows(剪贴板读取目前只实现了 Windows),以及 Node 20+ 与 Rust 1.82+(仅构建时需要)。

```bash
pnpm install
pnpm build          # 产出安装包
pnpm dev            # 开发模式
```

装完就完事了——没有第二步,不用去浏览器里加载任何东西。想装扩展的话见上面那一节。

## 隐私

- 剪藏**全程不经过任何服务器**。Quire 不联网、不写遥测、不上报。
- **不开任何监听端口。** 早期版本在本机起过一个 HTTP 服务接收扩展请求,现已删除;现在的扩展也走剪贴板,不重蹈覆辙。
- 剪贴板监控**默认关闭**,关着的时候 Quire 一个字节都不读你剪贴板。开着的时候也只做两件事:比对内容指纹、弹提示。**不自动保存、不上传、不记录历史。**
- 扩展只读你当前这一页的 DOM,只写剪贴板,不联网、不发任何请求。
- ⚠️ **文章中的图片目前仍从原站远程加载**,你的阅读行为会暴露给图片服务器。本地化图片在路线图里。

## 已知限制

- **只有 Windows 能用。** 剪贴板的 HTML 格式在 macOS 上机制不同,代码里目前直接返回"当前平台尚未支持",没给半残的实现。
- **扩展没在真实浏览器里实测过。** 打包产物通过了类型检查和构建,桌面端读它的元数据也有真实剪贴板往返测试兜着,但"点图标 → 浏览器接受写入 → Quire 收到"这一段只有人工验证过逻辑,没有自动化测试。
- **原文地址取决于源程序写不写。** CF_HTML 规范里地址可以放在 `SourceURL` 头、`<meta http-equiv="refresh">`、`<meta name="source-url">` 或 `<base href>`,这四处都做了兜底,但源程序一个都不写就只能空着(此时不显示「打开原文」,不编造地址)。
- **监控是轮询,不是事件。** 700ms 一次,极端情况下提示会晚半秒。Win32 的剪贴板变更通知需要注册窗口消息,复杂度高一档,第一版没做。
- 正文抽取用的是 [Defuddle](https://github.com/kepano/defuddle),对现代 JS 渲染页面的效果需要真实站点验证。
- macOS 打包未验证,目前只在 Windows 上实测过。
