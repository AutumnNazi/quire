# Quire

> Quire:一篇文章里的一叠折叠配页,也可以是一个"夹页"的错拼。

**Read later, on your own disk.**

**剪藏,留在你自己磁盘上。**

[![CI](https://github.com/AutumnNazi/quire/actions/workflows/ci.yml/badge.svg)](https://github.com/AutumnNazi/quire/actions/workflows/ci.yml)

---

剪下来的东西,就是你硬盘上一个普普通通的 Markdown 文件。不是哪家公司数据库里的一条记录。

没有账号,没有云端,没有订阅。装完就能用。

```
~/Documents/Quire/
└── clips/
    ├── 2026-09-28-m8x2k9a4-example-com.md
    ├── 2026-09-28-m8x2k1b7-github-com.md
    ├── 2026-09-27-m7y0z2c9-sspai-com.md
    ├── assets/            # 文章里的图片,剪藏时存下来的
    │   └── m8x2k9a4/
    │       └── 0.png
    └── .trash/            # 删除不是真删,东西在这儿等你后悔
```

记事本、Obsidian、随便什么编辑器都打得开。想换软件就换,想备份就备份,想直接扔进 Git 也随你。

## 安装

**去 [Releases 页](https://github.com/你的账号/quire/releases) 下对应的包**,双击即装,没有第二个步骤。

| 平台 | 拿哪个 |
| --- | --- |
| Windows | `Windows-x64-*-setup.exe`(推荐)或 `.msi` |
| macOS(M1/M2/M3/M4) | `macOS-Apple-Silicon-*.dmg` |
| macOS(Intel) | `macOS-Intel-*.dmg` |
| Linux | `.deb`(Debian/Ubuntu)或 `.AppImage`(免安装) |

⚠️ **macOS 和 Linux 的包没在真机上验证过**,详见下面「已知限制」。装之前先拿一篇网页试一下剪藏,有问题来提 issue。

## 装完之后

**两步,不用注册,不用登录,不用改任何设置。**

1. 在任意文章页里选中想留的那部分,`Ctrl`+`C`
2. 切到 Quire,按 `Ctrl`+`V`

第一条剪藏会存在 `~/Documents/Quire/` 下面——就是你自己硬盘上一个 `.md` 文件。

嫌切窗口麻烦?打开工具栏上的**「监控剪贴板」**,之后你在哪儿复制了东西,它会主动弹一条问你存不存。**它只问,不会自己存**,所以你复制的密码、验证码也一样会弹——该不该开你自己定。

## 存下来的怎么理

攒多了总得翻。工具栏上有四个切换:

- **全部** —— 都在这儿。
- **未读** —— 还没读的。读过一篇,列表项右下角的「标已读」点一下它就出去了;**Quire 不会自动帮你标**,你可能只是手滑点开了。
- **每周** —— 按自然周分组,每组顶上写着「第 N 周 — M 篇 · 还有 K 篇没读」。适合周末扫一眼这周欠了多少。
- **归档** —— 看完不打算再看的,在正文页点「归档」挪过来。**归档不是删除**,文件还在磁盘上,「全部」里照样看得见,在这儿也能翻回去。

搜索框搜的是标题和正文,中文两字就能搜(「苹果」「手机」都行)。搜的时候不套用上面的筛选——你搜出来的东西就是搜出来的东西,再筛一遍只会让你以为搜索坏了。

## 浏览器扩展(可选)

剪贴板存的是**你复制的那部分**。想留哪段就留哪段,不用事先挑好。

**光靠复制也够存整篇。** 剪贴板里带着网页地址、又没带整页的时候,Quire 会**自己**去把那一页抓下来:拿到标题、作者、发布时间,能抽出正文就一起存。抓不到也不影响——你复制的那段话照样存得下来,界面上会老实说「抓不到全文,已存你复制的内容」。

真要更完整的一版(整页原样、封面图、页面自带的那些元数据),可以再装个扩展。它把整页连同页面信息写进剪贴板,Quire 用现成的 `Ctrl`+`V` 接住,走的还是上面那条路:

```
你在别处 Ctrl+C  /  点一下扩展图标
   ↓  Windows 剪贴板(HTML Format + Unicode Text)
Quire 比对一次内容指纹(事件驱动,不是定时轮询)
   ↓  emit "clipboard-changed"
前端弹提示 → 你点「保存」
   ↓  Defuddle 在 webview 里把 HTML 转成 Markdown
vault/clips/2026-09-28-xxxx-example-com.md
```

扩展不新增端口,也不发任何网络请求。

```bash
pnpm ext:build
```

然后去 Chrome/Edge 的扩展管理页(`chrome://extensions`),把开发者模式打开,加载 `apps/extension/dist`。

用的时候点一下图标,图标上冒个 ✓,内容就已经进剪贴板了。监控剪贴板开着的话,Quire 会直接弹提示,连切窗口都省了。

> ⚠️ **这条链路还没在真实浏览器里跑通过。** 抽取逻辑有 13 条测试兜着,但「点图标 → 浏览器接受写入 → Quire 收到」这三步连起来,目前一次都没在真机上验过。装好之后请拿一篇真网页试一下,有问题告诉我。

## 为什么不让扩展变成必需品

剪藏工具的第一步,不该是"装个插件"。

装扩展要进扩展管理页、开开发者模式、加载目录、认扩展 ID,权限弹框还得点同意。这道坎一高,大部分人就在这儿走了。

所以扩展是可选的,不是前提。**不装,剪藏的每一步都还在**——现在连整篇正文都能靠复制时带的地址自己抓到。

## 为什么又是一个稍后读工具

因为大多数"稍后读"存下来的东西,其实是租的。

云端笔记服务哪天关门了,你那两千条笔记去哪儿?常见的结局是:变成一堆格式互不兼容的导出文件,链接全断了。搜索索引是公司的资产,不是你的。

Quire 就一个想法:

- **正文是文件,不是记录。** 一个剪藏就是一个 `.md`,带 YAML frontmatter,什么工具都读得动。
- **索引是能删的派生物。** 搜索跑在 SQLite FTS5 上,但那个索引**不是你的数据**:它只存在 Quire 自己的配置目录里,不进剪藏库、不跟着网盘同步,删掉之后搜索会自动重建,重建不了就退回逐文件扫描——最坏情况只是慢一点,一个字都不会少。所以不存在"索引坏了就丢东西""索引版本对不上"这种问题,也没有任何东西需要迁移。**正文永远是唯一真相。**
- **数据摆在你能看见的地方。** 工具栏上永远写着剪藏目录的完整路径,点一下直接用文件管理器打开。
- **不开监听端口。** 剪藏全在你本机里跑完,不会在你电脑上常驻一个 HTTP 服务——那等于给同浏览器里开着的恶意网页留个可攻击的口子。

## 自己构建

要自己构建的话,得有 Node 20+ 和 Rust 1.82+(macOS 还要 Xcode 命令行工具,Linux 还要 WebKitGTK 的开发头文件),软件装好之后就不用了。打 tag(`git tag v0.1.0 && git push origin v0.1.0`)会让 CI 出四个平台的包并挂成一个**草稿** Release——先自己装一遍,确认没问题再点发布。

```bash
pnpm install
pnpm build          # 产出安装包
pnpm dev            # 开发模式
```

`pnpm build` 跑完,Windows 上会出两个包:`bundle/nsis/` 里的 exe 安装程序(默认,双击就装)和 `bundle/msi/` 里的 msi(给企业批量部署用)。两个都能装,功能一样。

装完就完事了,没有第二步。想装扩展的话看上面那节。

## 隐私

- **Quire 自己不联网**:不写遥测,不上报,没有账号,没有云端。
- ⚠️ **有两处例外,得说清楚。**
  1. **剪藏的那一刻,Quire 会去图片服务器把文章里的图下载一次。** 之前是"读的时候才去连",现在改成"剪的时候连一次,存下来"。改的是**更早、更少**——同一篇文章你读十遍,图片服务器只在你剪的那一次知道你访问过,而且那一次你本来就在浏览它。下载完图片存在 `clips/assets/` 里,以后打开这篇再也不联系任何人。
     - 图挂了的(404、服务器不给、超出大小上限)不会被改写,还是指着原站,不会凭空多一个裂图。
  2. **剪贴板里带着网页地址时,Quire 会去访问那个地址一次**,把整页抓下来自己抽正文。这是**你本来就在看的那一页**,而且请求在你按下保存的那一刻就发出去了,只发一次。抓取带着 Quire 自己的 User-Agent(不装任何跟踪),抓回来的东西只留在本机。
     - 默认 20 秒超时、8 秒连不上就放弃。**抓不到就算**,不会重试、不会转给别人、不会缓存到别处。
     - 单页超过 20MB 直接不抓——这种页面塞进界面会卡住好几秒。
- **不开任何监听端口。** 扩展和桌面端之间走的是剪贴板,不是网络,不会在你机器上常驻一个 HTTP 服务。
- 剪贴板监控**默认关着**。关着的时候 Quire 一个字节都不读你的剪贴板;开着的时候也只干两件事——比一下内容有没有变、弹个提示。**不自动存,不上传,不留历史。**第一次开的时候会问你要不要开,答完记下来,不再问第二次。
- 扩展只读你当前这一页的内容,只往剪贴板里写东西,不联网,也不发任何请求。

```bash
pnpm clippy         # 零警告
pnpm typecheck      # 两个包的类型检查
pnpm ext:build      # 浏览器扩展
```

架构和数据格式的细节在 [docs/architecture.md](docs/architecture.md)。

## 已知限制

- **扩展没在真浏览器里跑过。** 打包产物过了类型检查和构建,桌面端读它的元数据也有真实剪贴板的往返测试兜着。可"点图标 → 浏览器肯写 → Quire 收到"这一段只人工验过逻辑,没有自动化测试。
- **原文地址看源程序肯不肯给。** CF_HTML 规范里地址可能放在 `SourceURL` 头、`<meta http-equiv="refresh">`、`<meta name="source-url">` 或者 `<base href>`,这四处我们都兜住了。可它要是一个都不写,我们就只能空着——这时候不显示「打开原文」,也不会给你编一个出来。
- **剪贴板监控在 Windows 上是事件驱动的,别的平台还是轮询。** Win32 的 `AddClipboardFormatListener` 让系统一改就通知;注册不上(会话 0、远程桌面断开)会自动退回 700ms 轮询,并留一条 30 秒的兜底心跳,免得某条通知没派发到就再也不响。macOS 上目前只有轮询。
- **文件监控会漏掉「剪藏的同一瞬间手改的那一次」。** Quire 自己写盘之后 3 秒内到达的磁盘事件一律当作自己的写盘丢掉,免得每次剪藏都跟着一次全量重扫。你在这 3 秒里手动改了同一个文件,那次改动要等下一次外部事件或手动刷新才出现。这是权衡出来的:精确按文件排除需要 Quire 记得自己写过哪些路径,那个集合和实际写盘是两条独立的路,中间隔一层就一定对不齐,而对不齐的代价是「莫名其妙不更新」——比偶尔晚 3 秒难查得多。
- **网盘同步目录上的文件监控不可靠。** OneDrive 之类的同步盘在本地不一定产生系统事件。碰到这种情况还得靠手动刷新。
- 正文抽取用的是 [Defuddle](https://github.com/kepano/defuddle),碰上现代 JS 渲染的页面效果怎么样,还得拿真实站点试试。
- **手动刷新(`F5` 或工具栏)还在,别删。** 文件监控只监听剪藏目录那一层,监听器起不来的时候(目录刚被网盘换掉、权限变了)它是唯一的救命绳。切回窗口时自动重扫那条也还留着。
- **macOS 和 Linux 的包没在真机上验证过。** 打 tag 会由 CI 出四个平台的包,但那几个平台的一次都没在真实机器上装过。macOS 的剪贴板(NSPasteboard 那条)更是照文档写的,连代码都没跑起来过。**Windows 那个验证得多一些**,也不代表每个人都能装上——CI 出的 Release 是草稿状态,先自己装一遍再决定发不发。
- **抓不到全文是正常结局。** 需要登录的页面、纯 JS 渲染的页面、拦爬虫的站点,自己抓都会失败——这时候存的是你复制的那段,界面上也会说清楚。想稳拿整篇就用扩展,或者过几天在详情页点「补全全文」重试一次。**这不是 bug,是一条设计**:抓取失败不该把你已经复制到手的东西也弄没。
- **补全全文只在新正文更长时才写。** 页面改了、抽出来只剩个壳的时候,拿它覆盖掉你已有的内容是净损失,那就原样不动。
- **搜不到的时候现在不再是死路,但它仍然是弱手段。** 差一个字的容错按**编辑距离 ≤ 1** 算(「手机」能命中「手记」,差两个字的「智能手机」不行——「手机」变「智能手机」是**插了两个字**);而且**至少要有一半的词条对得上**,否则长查询里几乎每一篇都能凑上一个,那不叫近似命中,那叫全库。繁简只差一个字,所以**算命中**,这是故意的。**近似结果一律不高亮**——我们不知道你打错的是哪个字,标出来是蒙的。
- **「还没做完的」清单数的是当下的文件,不是记下来的事件。** 图还指着外站的,是真去正文里数 `![...](http…)`;没抓到全文的,是"有能抓的地址 + 正文短于 500 字"。它**不记**"当初失败了几张"——那份记录会过期,而一份过期的账比没有账更坏。
- **搜不了拼音。** 分词是二元组加单字:「苹果手机」切出「苹果」/「果手」/「手机」和「苹」/「果」/「手」/「机」,所以「苹果」和单字「苹」都搜得到。
  - 2026-09-29 判断这轮不做拼音:让每个词条多派生一串拼音,搜索那条热路径会明显变慢,而用户多半记得自己读过什么字,直接打中文更省事。
  - 2026-10-01 重启过这个决定,**依然没做**,但理由变了:手写一张拼音表在多音字上是错的(「行」读 xíng 还是 háng 得看词),而这台机器上没有能拿到可靠数据的来源——`pip` 装不上,也不打算为了一个搜索功能往项目里塞一份来路不明的数据表。**宁可搜不到,不要搜错。** 真要上,得先找到一个可信的拼音数据源,那是一次单独的工程,不是一个功能点。
- **单篇最多存 200 张图。** 单张上限 20MB 之外还有一道总张数的闸(`assets.rs` 的 `MAX_IMAGES_PER_CLIP`),超出的图**留在 .md 里指向原网址**,不会被悄悄丢掉——计数会计进「失败 N 张」那个提示里。绝大多数文章碰不到这个数,但图集类的页面会。
- **扩展的文案跟着浏览器语言走,不能单独切。** 桌面端有按钮能手动换语言,扩展没有——它只能读 `chrome.i18n` 给的界面语言。想让英文用户强制看中文提示,只能改浏览器设置。
- **批注只认字面块标量(`note: |`)。** Quire 自己写、自己读都走这个格式,Obsidian 之类也认。但 YAML 的折叠块(`note: >`,自动折行)读进来会被当纯文本,内容里的换行原样留着。手写折叠块的人不多,可这是**已知不支持**,不是没想过。
- **批注不显示在列表里。** 只在详情页能看能改。列表行已经挤了标题、站点、时间、标签,再塞一段用户自己写的话,一行放不下。真要在列表里显示,得先定"显示第几行、显示多长"这类规则。
- **冲突保护管不了「两个人同时按保存」这一种。** 它比的是「你打开这篇时磁盘上那份」和「此刻磁盘上那份」——中间隔的时间越久越有用武之地,但两次写入之间的窗口(几十毫秒)它挡不住,那需要锁,而锁在跨进程编辑同一份 Markdown 的场景里(Obsidian / 记事本 / Git)本来就装不起来。**批量操作不带这个保护**:批量是「对选中这批做同一件事」,没有「我正在编辑哪一篇」这个上下文,给不出该比什么。
- **列表一次只画 200 条,但搜索覆盖全库。** 搜索是另一条路(后端扫全文),所以「库里有两千篇,搜一个只有旧的才有的词」照样搜得到。上限只影响**翻列表**:翻到第 200 条之后要点一下「再显示 200 篇」。`Ctrl`+`A` 全选也只选**画出来的那些**——这是故意的,看不见的跟着一起删掉才是事故。
- **统计页算的是内存里那份列表,不是一个独立的数据源。** 好处是打开就出数字,不用等一次全库扫描;代价是它和磁盘最多差一次刷新。但列表也在内存里,两边一致。
