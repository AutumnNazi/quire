# Quire

> Quire:一篇文章里的一叠折叠配页,也可以是一个"夹页"的错拼。

**Read later, on your own disk.**

**剪藏,留在你自己磁盘上。**

[![CI](https://github.com/AutumnNazi/quire/actions/workflows/ci.yml/badge.svg)](https://github.com/AutumnNazi/quire/actions/workflows/ci.yml)

---

剪下来的东西,就是你硬盘上一个普普通通的 Markdown 文件。不是哪家公司数据库里的一条记录。

没有账号,没有云端,没有订阅。装完就能用。

```
~/Documents/Quire/
└── clips/
    ├── 2026-09-28-m8x2k9a4-example-com.md
    ├── 2026-09-28-m8x2k1b7-github-com.md
    └── 2026-09-27-m7y0z2c9-sspai-com.md
```

记事本、Obsidian、随便什么编辑器都打得开。想换软件就换,想备份就备份,想直接扔进 Git 也随你。

## 怎么剪藏

**复制,然后粘贴。** 就这两步。

1. 在文章页里选中想留的那部分,`Ctrl`+`C`
2. 切到 Quire,按 `Ctrl`+`V`(或者点工具栏上的「粘贴剪藏」)

懒得切窗口?把工具栏的**「监控剪贴板」**打开(默认是关的)。之后你在哪儿复制了东西,Quire 都会在底下弹一条,问你存不存。

它只问,不会自己存。你复制的密码、验证码、快递单号,该弹还是弹——所以这个开关该不该开,你自己定。

## 浏览器扩展(可选)

剪贴板存的是**你复制的那部分**。想留哪段就留哪段,不用事先挑好。

要是你还想要**整篇**,或者想把作者、发布时间、封面图一块儿存进去,可以再装个扩展。它把整页连同页面自带的那些信息写进剪贴板,Quire 用现成的 `Ctrl`+`V` 接住,走的还是上面那条路:

```
你在别处 Ctrl+C  /  点一下扩展图标
   ↓  Windows 剪贴板(HTML Format + Unicode Text)
Quire 每 700ms 比对一次内容指纹(仅在开关打开时)
   ↓  emit "clipboard-changed"
前端弹提示 → 你点「保存」
   ↓  Defuddle 在 webview 里把 HTML 转成 Markdown
vault/clips/2026-09-28-xxxx-example-com.md
```

扩展不新增端口,也不发任何网络请求。

```bash
pnpm ext:build
```

然后去 Chrome/Edge 的扩展管理页(`chrome://extensions`),把开发者模式打开,加载 `apps/extension/dist`。

用的时候点一下图标,图标上冒个 ✓,内容就已经进剪贴板了。监控剪贴板开着的话,Quire 会直接弹提示,连切窗口都省了。

> ⚠️ **这条链路还没在真实浏览器里跑通过。** 抽取逻辑有 13 条测试兜着,但「点图标 → 浏览器接受写入 → Quire 收到」这三步连起来,目前一次都没在真机上验过。装好之后请拿一篇真网页试一下,有问题告诉我。

## 为什么不让扩展变成必需品

剪藏工具的第一步,不该是"装个插件"。

装扩展要进扩展管理页、开开发者模式、加载目录、认扩展 ID,权限弹框还得点同意。这道坎一高,大部分人就在这儿走了。

所以扩展是可选的,不是前提。**不装,剪藏的每一步都还在。**

## 为什么又是一个稍后读工具

因为大多数"稍后读"存下来的东西,其实是租的。

云端笔记服务哪天关门了,你那两千条笔记去哪儿?常见的结局是:变成一堆格式互不兼容的导出文件,链接全断了。搜索索引是公司的资产,不是你的。

Quire 就一个想法:

- **正文是文件,不是记录。** 一个剪藏就是一个 `.md`,带 YAML frontmatter,什么工具都读得动。
- **压根没有索引。** 搜索是每次现扫 `.md` 文件算出来的,所以不存在"索引坏了""索引版本对不上"这种问题——**没有任何东西需要重建,也没有任何东西需要迁移**。真到了扛不住的规模,再上索引,那时它也是能删的派生物。
- **数据摆在你能看见的地方。** 工具栏上永远写着剪藏目录的完整路径,点一下直接用文件管理器打开。
- **不开监听端口。** 剪藏全在你本机里跑完,不会在你电脑上常驻一个 HTTP 服务——那等于给同浏览器里开着的恶意网页留个可攻击的口子。

## 安装

Windows 和 macOS 都能用(剪贴板这两块都做了)。**macOS 那份没有在真机上验证过**,你用之前先拿一篇网页试一下,有问题跟我说。要自己构建的话,得有 Node 20+ 和 Rust 1.82+,软件装好之后就不用了。

```bash
pnpm install
pnpm build          # 产出安装包
pnpm dev            # 开发模式
```

装完就完事了,没有第二步。想装扩展的话看上面那节。

## 隐私

- 剪藏**全程不过任何服务器**。Quire 不联网,不写遥测,不上报。
- **不开任何监听端口。** 扩展和桌面端之间走的是剪贴板,不是网络,不会在你机器上常驻一个 HTTP 服务。
- 剪贴板监控**默认关着**。关着的时候 Quire 一个字节都不读你的剪贴板;开着的时候也只干两件事——比一下内容有没有变、弹个提示。**不自动存,不上传,不留历史。**
- 扩展只读你当前这一页的内容,只往剪贴板里写东西,不联网,也不发任何请求。
- ⚠️ **文章里的图片现在还是从原站远程加载**。你打开一篇文章,图片服务器就知道你看了这篇。要把图片也存到本地,还在路线图里。

## 已知限制

- **只有 Windows 能用。** 剪贴板的 HTML 格式在 macOS 上是另一套机制,代码里现在直接返回"当前平台尚未支持",没给你个半残的实现。
- **扩展没在真浏览器里跑过。** 打包产物过了类型检查和构建,桌面端读它的元数据也有真实剪贴板的往返测试兜着。可"点图标 → 浏览器肯写 → Quire 收到"这一段只人工验过逻辑,没有自动化测试。
- **原文地址看源程序肯不肯给。** CF_HTML 规范里地址可能放在 `SourceURL` 头、`<meta http-equiv="refresh">`、`<meta name="source-url">` 或者 `<base href>`,这四处我们都兜住了。可它要是一个都不写,我们就只能空着——这时候不显示「打开原文」,也不会给你编一个出来。
- **监控是轮询,不是事件。** 700ms 问一次,再极端的时候提示也会晚个半秒。Win32 的剪贴板变更通知得注册窗口消息,麻烦一档,第一版没做。
- 正文抽取用的是 [Defuddle](https://github.com/kepano/defuddle),碰上现代 JS 渲染的页面效果怎么样,还得拿真实站点试试。
- macOS 的打包还没试过,现在只在 Windows 上跑得通。
